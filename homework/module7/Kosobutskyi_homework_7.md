# Homework Module 7 — Аналіз життєвого циклу контейнера

## 1. Команда запуску контейнера

```bash
docker run -d --name hw7-http -p 8080:8080 python:3.12-slim sh -c "python -m http.server 8080"
```

Ця команда запускає контейнер на основі образу `python:3.12-slim`, відкриває зовнішній порт `8080`, і всередині контейнера запускає команду `sh -c "python -m http.server 8080"`.

## 2. Який процес є PID 1 усередині контейнера

Виконана перевірка всередині контейнера:

```bash
docker exec hw7-http python -c "import pathlib; p=pathlib.Path('/proc/1/cmdline').read_bytes(); print('CMDLINE:', p.replace(b'\x00', b' ').decode('utf-8', 'replace')); print(); print(pathlib.Path('/proc/1/status').read_text())"
```

Результат:

- `CMDLINE: sh -c python -m http.server 8080`
- `Name:   sh`
- `Pid:    1`
- `PPid:   0`

### Пояснення

PID 1 всередині контейнера — це процес `/bin/sh`, який викликаний Docker для виконання команди `sh -c ...`. Цей процес є головним процесом контейнера, і він визначає життєвий цикл контейнера. Якщо PID 1 завершується, контейнер також завершується.

## 3. Завершення контейнера та сигнали

Команда зупинки:

```bash
docker stop hw7-http
```

### Що відбувається:

- `docker stop` спочатку надсилає сигнал `SIGTERM` процесу з PID 1.
- якщо процес не завершився за стандартний час очікування (10 секунд), Docker надсилає `SIGKILL`.

### Статус завершення

Контейнер завершився зі статусом `Exited (137)`, що відповідає завершенню через `SIGKILL` (`128 + 9 = 137`). Це означає, що процес не встиг або не захотів коректно завершитися після `SIGTERM`, і Docker примусово зупинив його.

### Якщо процес ігнорує `SIGTERM`

Якщо головний процес контейнера ігнорує `SIGTERM`, контейнер продовжує працювати доти, поки Docker не надішле `SIGKILL` після таймауту. `SIGKILL` не може бути ігнорований, і він примусово завершує процес.

## 4. Логи контейнера

Команда:

```bash
docker logs hw7-http
```

Результат: порожній вивід.

### Пояснення

Docker зберігає журнали контейнера з його стандартного потоку виводу (`stdout`) та стандартного потоку помилок (`stderr`). В даному випадку Python HTTP-сервер не виводив жодних повідомлень у консоль, тому логів немає.

## Висновок

Життя контейнера визначається процесом з PID 1 всередині контейнера. Контейнер почався з процесу `sh`, який виконував `python -m http.server 8080`. Коли `docker stop` надіслав `SIGTERM`, якщо б процес не завершився швидко, Docker примусово завершив його `SIGKILL`, і контейнер вийшов з кодом `137`.
